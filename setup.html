# Наряд-допуски ДЭСД — подключение регионов

В комплекте два интерфейса: dist/index.html — личный кабинет, dist/monitor.html — мониторинг на основе исходной карты. Их можно разместить вместе либо на двух разных хостингах. Региональных серверов пока нет: их адреса пользователь не предоставил. Интерфейс работает для заполнения и экспорта без базы, но не имитирует регистрацию или открытие нарядов.

## Как проходит работа
1. Пользователь выбирает регион, регистрируется с ФИО, телефоном, подразделением и своим паролем.
2. Выбирает ККС, ВЛС либо электроустановки. Заполняет реестр и сам бланк. В образцах есть примерные данные — их нужно заменить.
3. Скачивает настоящий DOCX либо нажимает «Печать / PDF» и выбирает принтер или «Сохранить как PDF» в браузере. Разбиение страниц в браузере может отличаться от Word. Проверить перед подписанием.
4. Подписывает распечатанный документ, загружает все подписанные страницы (фото или PDF), подтверждает проверку, нажимает «Открыть наряд».
5. Второй сайт получает сведения по всем подключённым регионам: открыто/закрыто, подразделение, производитель, телефон и подписанные вложения.
6. Производитель завершает работы и закрывает наряд в личном кабинете. Запись и фотографии остаются в истории.

Система проверяет наличие, тип и размер вложений, но не распознаёт подписи и не удостоверяет юридическую действительность наряда. Это подтверждает производитель работ. Каждый логин имеет доступ только к собственным нарядам через защищённое API. В публичном мониторинге намеренно доступны сведения и подписанные страницы, как предусмотрено заданием. Регистрация самостоятельная; подтверждение личности, восстановление пароля и админка управления учётными записями в эту версию не включены.

## Один сервер для одного региона
Нужен постоянно работающий сервер или корпоративная виртуальная машина с Node.js 24+ либо Docker, диском и HTTPS. Домашний компьютер, который выключают, для этого не подходит.

Каждый регион получает свою копию папки backend, свой DATA_DIR и свой адрес HTTPS. Внутри DATA_DIR находятся база permits.sqlite и папка files. Не размещайте их в публичной папке сайта. Несколько регионов нельзя направлять на одну и ту же папку данных.

### Вариант Docker
1. Установить Docker на сервер региона.
2. В compose.yaml задать точное название REGION из списка dist/regions.json. Пример: «Актюбинский ДЭСД».
3. В ALLOWED_ORIGINS указать адрес первого сайта и адрес второго сайта через запятую, без завершающего слеша. Если обе страницы находятся на одном домене, достаточно одного адреса. Адреса со схемой https:// обязательны.
4. Выполнить в папке backend: `docker compose up -d --build`.
5. Настроить внешний HTTPS reverse proxy на 127.0.0.1:8080. Для nginx: client_max_body_size 36m; proxy_read_timeout 60s; proxy_pass http://127.0.0.1:8080; . Сертификат должен быть действительным. Домен и сертификат предоставляет администратор региона.
6. Открыть https://АДРЕС-БАЗЫ/health — должен вернуться {ok:true,region:...} с нужным названием.
7. Повторить на серверах остальных регионов с их именами, дисками и адресами.

### Вариант без Docker
Node.js 24+ установлен. Пример для Linux:
```
REGION='Актюбинский ДЭСД' ALLOWED_ORIGINS='https://АДРЕС-ПЕРВОГО-САЙТА,https://АДРЕС-ВТОРОГО-САЙТА' DATA_DIR='/srv/nd-aktobe' PORT=8080 node server.mjs
```
Настроить systemd или другой менеджер процессов для автоматического старта и HTTPS proxy. Проверка сервера: `node verify.mjs` (временная отдельная тестовая база, рабочие данные не затрагиваются).

## Привязка обоих сайтов
1. На первом сайте открыть «Подключение регионов».
2. Для каждого готового региона указать его HTTPS-адрес без /api, например https://nd-aktobe.example.kz.
3. «Сохранить в браузере» удобно для проверки, но действует только в этом браузере и на этом домене.
4. Нажать «Скачать config.json». Заменить этим файлом dist/config.json на хостинге первого и второго сайта. Так все посетители получат одни и те же адреса. На двух разных доменах локальные настройки не синхронизируются.
5. Обновить оба сайта. Зарегистрировать тестовых производителей и пройти открытие/закрытие. Перед рабочим запуском удалить тестовую базу только если на ней нет рабочих документов, либо использовать отдельный тестовый DATA_DIR.
6. Мониторинг обновляется раз в 30 секунд. Недоступные регионы показаны прочерком, а не нулём; итог обозначен как неполный.

Пример config.json (реальный адрес нужно вписать вместо примера):
```
{"endpoints":{"Актюбинский ДЭСД":"https://nd-aktobe.example.kz"}}
```

## Размещение интерфейсов
Загрузить содержимое dist на статический HTTPS-хостинг. Не открывать index.html двойным щелчком: для шаблонов используются HTTP-запросы. Первый сайт: /index.html, второй: /monitor.html. Для отдельного второго домена перенести monitor.html, regional-monitor.js, config.json и исходные ресурсы; проще скопировать dist целиком. Подписи и данные не хранятся на статическом хостинге.

Карта и старые вопросы сохранены из предоставленного HTML. Старый Google Apps Script для вопросов независим от новой базы НД: если он недоступен, вопросы не загружаются, но мониторинг НД работает самостоятельно. Исторические наряды из старой базы автоматически не переносятся; для миграции нужен согласованный экспорт и привязка владельцев.

## Резервные копии и доступ
Резервировать DATA_DIR на стороне каждого региона. Для согласованной копии остановить контейнер, скопировать данные и запустить контейнер снова, либо использовать online backup SQLite и согласованную копию файлов. Проверять восстановление. Доступ к диску и резервным копиям выдаёт администратор региона. Пароли хешируются scrypt; сеанс действует 12 часов. В production использовать только HTTPS. CORS ограничивает браузерные обращения разрешёнными сайтами, серверное владение проверяется токеном. Публичные API мониторинга не требуют логина; блокировку их публичности нужно менять отдельно, если изменится задача.

Эта версия не включает ЭЦП, автоматическую проверку подписей и корпоративную проверку допуска к работе. Она ведёт учёт на основании загруженных производителем подписанных экземпляров.
